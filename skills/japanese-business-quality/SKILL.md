# 日本語ビジネス文書校正 Skill v1.2

## 目的
日本語として文法が正しいだけでなく、日本企業の営業責任者・技術責任者・経営企画担当者が実際に書くような、自然で簡潔な顧客向け文章に整える。文章の美しさより、**元の意味・事実・数値を守ること**を優先する。

## 適用対象
提案書、営業資料、PowerPointのスライド文言、会社案内、技術比較レポート、顧客向けメール、Markdown、Word、PDFなど。ファイルの直接編集は実行環境の対応機能がある場合に限る。

## 校正の基本方針
1. **結果を先に伝える。** 「〜ということが確認されました」より「〜件中〜件を検出しました」のように、事実を直接書く。
2. **受動表現を必要以上に使わない。** 「確認されました」「示されました」「実施されました」「期待されます」の連続を避ける。ただし「個人情報は暗号化されます」など、状態や対象を主題にする方が自然なら残す。
3. **能動態への機械的な置換をしない。** 主語、責任主体、推測と事実の区別を維持する。「期待されます」を無条件に「目指します」へ変えると意味が変わるため禁止。
4. **直訳調・抽象表現を減らす。** 「シームレス」「エンパワー」「革新的なソリューション」などは、根拠のある具体的な機能や効果で説明する。
5. **過剰な敬語を避ける。** 顧客向け本文は原則「です・ます調」。スライド見出しは簡潔な名詞句や短い言い切りを使う。「〜させていただきます」を多用しない。
6. **技術用語を正確に扱う。** 顔検出と顔認証、認識精度と把持成功率、推論時間と処理全体の遅延などを混同しない。
7. **冗長な報告調を削る。** 「〜という結果が得られました」「〜であることが明らかになりました」は、意味が変わらない範囲で短くする。
8. **数値と根拠を守る。** モデル名、製品名、単位、測定条件、サンプル数、契約条件、法的表現、引用、否定・条件文を勝手に変えない。
9. **実証・計画・推測を区別する。** 実測していない性能を断定しない。未確認事項は「要確認」と明記する。
10. **文章のリズムを整える。** 同じ文末や同じ主語の繰り返しを避け、段落ごとに主張・根拠・判断を整理する。

## 実行手順
1. **文書を把握する。** 読者、目的、文体、技術分野、表・図・見出しとの関係を確認する。指定がなければ日本企業向けB2B資料として扱う。
2. **原文の事実を抽出する。** 数値、固有名詞、技術仕様、主張、測定条件、責任主体、留保条件を一覧化して保護する。
3. **問題を検出する。** 不自然な受動表現、直訳調、過剰敬語、曖昧な主語、重複、用語の揺れ、根拠のない断定、論理の飛躍を調べる。
4. **自然な日本語に書き直す。** 可能な限り結果を先に書き、短い能動文を優先する。原文の意味や確実性を変えない。
5. **原文と照合する。** 数値・条件・単位・主張・責任主体・否定・将来計画の扱いを一つずつ確認する。
6. **品質を評価する。** `references/rubric.md` に沿って採点し、重大な意味変更があれば不合格とする。
7. **成果物を提示する。** 修正文、主な修正理由、要確認事項、品質評価を示す。資料ファイルを編集した場合はレイアウト崩れも確認する。

## 出力形式
### 修正文
校正後の完成文章。原文の見出し・表構造をできるだけ維持する。

### 主な修正
変更前 → 変更後 → 修正理由。重要な変更を優先する。

### 要確認事項
測定条件の矛盾、根拠不足、技術用語の曖昧さなど。なければ「なし」。

### 品質評価
100点満点の参考評価と、提出可／要確認／再校正の判定。

## 禁止事項
- 根拠のない「業界最高」「完全」「必ず」「100%」を追加しない。
- 数値・日付・製品名・モデル名・法的条件・契約条件を無断で変更しない。
- 実測結果から未検証のシステム全体の性能を推定して断定しない。
- 受動態を一律に禁止しない。
- 内容が不明な箇所を推測で補完しない。
- 校正のために原文の結論を強めたり弱めたりしない。

## 関連ファイル

## 最優先：翻訳調を排除し、日本語として組み立て直す
英語の構文を日本語の単語に置き換える校正は禁止する。まず原文の事実・意図・読者に伝える要点を把握し、その内容を日本語ネイティブの担当者が最初から執筆するならどう書くかを考えて、文と段落を再構成する。これは英文原稿が存在しないAI生成文にも適用する。

### 翻訳調を見分ける観点
- 「このソリューションは〜を可能にします」「〜を提供します」など、無生物を主語にした英語直訳型の連続
- 「私たちは」「この」「それは」の不必要な反復。日本語では文脈上明らかな主語を省略する
- 「〜することによって」「〜ということ」「〜の実現を可能にする」などの名詞化・冗長化
- 「一方で」「さらに」「その結果」などの接続詞を英語の論理構造に合わせて過剰に挿入する文章
- 「高い柔軟性を提供」「価値を提供」「重要な役割を果たす」など、具体的な行為を曖昧にする抽象表現
- 「確認されました」「示されました」など、受動的な報告調の反復
- 「〜を通じて」「〜において」「〜に関して」などを必要以上に重ねた硬い表現

### 書き直しの手順
1. 原文の意味を「誰が／何を／どうする／どの条件で／結果は何か」に分解する。
2. 原文の英文風の語順や一文の長さを引き継がず、読者に必要な結果・判断から書く。
3. 日本語として自然な主語の省略、短い述語、具体的な動詞を選ぶ。
4. 同じ文末が続く場合は、文の構造から変える。語尾だけを置換しない。
5. 原文と照合し、数値、技術的な意味、条件、責任、推測の強さが変わっていないか確認する。
6. 最終確認では文章を音読するつもりで読み、日本人の技術営業担当者が顧客にそのまま説明して違和感がないかを判断する。

### 注意
「自然な日本語」を理由に、存在しない顧客課題や効果を追加しない。曖昧な原文を具体化するには根拠が必要。契約条項、法令の引用、技術規格などでは定型表現を尊重する。英語の専門用語が業界で定着している場合は無理に和訳しない。

## 日本語の言い回し・語順・論法・文脈の最適化（必須）
校正対象は単語や文末だけではない。文、段落、資料全体の情報設計を確認し、日本語の読み手に自然に伝わるよう再構成する。

### 言い回し
- 直訳した熟語・抽象名詞・不自然な助詞の組み合わせを見直し、業界と読者に合う慣用的な日本語を選ぶ。
- 「〜を可能にする」「〜を提供する」「〜の実現に貢献する」を機械的に繰り返さない。具体的な動作や結果が原文で裏付けられる場合は、動詞を使って簡潔に書く。
- です・ます調、である調、体言止めを文書の用途に応じて使い分け、同一段落では原則として文体を統一する。

### 語順・情報構造
- 読み手が最初に知りたい結論や結果を先に置き、必要な条件・根拠・例外を後に続ける。ただし条件を先に示さないと誤解を招く場合は条件を優先する。
- 長い修飾語と被修飾語を近づけ、係り受けを明確にする。否定や限定の作用範囲を変えない。
- 文脈上明らかな主語は省略できるが、担当者・責任・権限が曖昧になる場合は省略しない。
- 一文に複数の結論を詰め込まず、必要に応じて分割する。逆に短文の連発で読みづらい場合は統合する。

### 論法・説得の組み立て
- 顧客向け提案書：顧客の課題 → 提案内容 → 仕組み・根拠 → 導入効果（実証と見込みを区別）→ 次の判断。
- 技術評価レポート：評価目的・条件 → 実測結果 → 比較 → 解釈と制約 → 推奨事項。
- 経営向け要約：結論 → 判断理由 → 投資・リスク・前提 → 意思決定事項。
- 文書の目的に応じて構成を選び、英語式の段落展開を無条件に引き継がない。
- 「事実」「解釈」「提案」を混同しない。因果関係が立証されていないときは、相関や観察結果を因果として記述しない。
- 反論や制約条件を隠さず、結論の強さを証拠に合わせる。

### 文脈と文章のリズム
- 指示語（これ・それ・当該）を多用せず、必要な箇所では具体的な対象名を再掲する。
- 「また」「さらに」「一方で」「したがって」を接続関係が明確な場合だけ使用する。
- 同じ語尾、名詞化、受動表現の連続を避ける。ただし変化を付けるためだけの不自然な言い換えはしない。
- 見出し、本文、表、注記で同じ概念を一貫して表現する。

### 仕上げの品質確認
1. 日本語ネイティブの担当者が初めから日本語で執筆した文章として自然か。
2. 語順と係り受けに曖昧さがないか。
3. 段落の主張と根拠が対応しているか。
4. 読者に求める判断・次の行動が明確か。
5. 数値・技術的意味・条件・確実性・責任主体を変えていないか。
